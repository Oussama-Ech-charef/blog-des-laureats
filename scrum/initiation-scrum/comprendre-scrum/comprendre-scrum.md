# Comprendre l'approche Agile et Scrum

## 1. Introduction

Agile est une approche flexible pour développer un logiciel.

Scrum est un framework Agile. Il organise le travail avec des Sprints.

## 2. Agile vs Cycle en V

**Cycle en V :**
- Travail étape par étape.
- Plan fixe.
- Livraison à la fin.
- Changement difficile.

**Agile :**
- Travail en petites étapes.
- Plusieurs Sprints.
- Livraison progressive.
- Adaptation aux changements.

**Exemple :** Avec Agile, nous développons notre projet Billetterie en plusieurs étapes.

## 3. Les 4 valeurs Agile

1. **Personnes et échanges :** communiquer et travailler ensemble.
2. **Logiciel fonctionnel :** créer un logiciel qui fonctionne.
3. **Collaboration client :** écouter le client.
4. **Adaptation au changement :** accepter les changements.

## 4. Les 3 piliers Scrum

- **Transparence :** le travail est clair.
- **Inspection :** vérifier le travail.
- **Adaptation :** améliorer le travail.

## 5. Les 3 rôles Scrum

**Product Owner :**
- Définit les besoins.
- Organise les priorités.
- Gère le Product Backlog.

**Scrum Master :**
- Aide l'équipe.
- Supprime les obstacles.
- Explique Scrum.

**Developers :**
- Développent le produit.
- Écrivent le code.
- Testent les fonctionnalités.

## 6. Les 5 événements Scrum

1. **Sprint :** période de travail d'un mois maximum.
2. **Sprint Planning :** préparer le travail.
3. **Daily Scrum :** réunion quotidienne de 15 minutes maximum.
4. **Sprint Review :** présenter le résultat et recevoir les avis.
5. **Sprint Retrospective :** améliorer le travail de l'équipe.

## 7. Increment et Definition of Done

**Increment :** une partie du produit qui fonctionne.

**Definition of Done (DoD) :** les critères pour terminer une tâche.

Exemple :
- Code terminé.
- Fonctionnalité testée.
- Tests réussis.

## 8. Application : Projet Billetterie

**Product Goal :** créer une application Web pour gérer les événements.

**Product Backlog :**
- Ajouter un événement.
- Afficher les événements.
- Modifier un événement.
- Supprimer un événement.
- Gérer les catégories.

**Sprint 1 :**

- Durée : une semaine.
- Sprint Goal : ajouter et afficher les événements.

**Tâches :**
1. Créer la base de données MySQL.
2. Créer le formulaire.
3. Afficher les événements.
4. Tester le travail.

**Increment :** une première version fonctionnelle avec l'ajout et l'affichage des événements.

## 9. Conclusion

Agile permet de travailler avec flexibilité.

Scrum organise le travail avec des rôles, des événements et des Sprints.

Chaque Sprint améliore le produit.
